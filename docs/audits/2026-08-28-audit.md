### 2.1 Class A+B — encoding/mojibake + missing subprocess/SSH timeouts

#### [HIGH] A+B — `mac_analyze_sets.py`: no SSH_OPTS, no timeouts, no UTF-8 encoding, no shlex.quote *(carried from 2026-08-17)*

**File:** `scripts/mac_analyze_sets.py` · Lines 50–52, 93, 99–102, 148–149  
**Status:** confirmed present — **unfixed**

All four subprocess/ssh call sites lack the `loop_hardening` treatment:

- `ssh_pi()` (line 50): `subprocess.run(["ssh", PI_HOST, ...], text=True)` — no `SSH_OPTS`, no `timeout=`, no `encoding='utf-8', errors='surrogateescape'`.
- `rsync_in()` (line 93): `subprocess.check_call(["rsync", "-q", ...])` — no rsync `--timeout`, no subprocess `timeout=`, no `shlex.quote()` on the remote path.
- `rsync_stems_out()` (lines 99–102): ssh mkdir + rsync — no `SSH_OPTS`, no `timeout=`.
- `push_set_rows()` (lines 148–149): `subprocess.run(["ssh", PI_HOST, ...], text=True)` — no `SSH_OPTS`, no `timeout=`, no encoding.

Compare: `mac_analyze_loop.py` imports `SSH_OPTS`, `SSH_QUERY_TIMEOUT`, `SSH_PUSH_TIMEOUT`, `RSYNC_IO_TIMEOUT`, `RSYNC_TIMEOUT`, and `TEXT_KW` from `loop_hardening.py` and passes them to every call.

**Fix:** Import hardening constants from `loop_hardening`; apply to all four call sites.

### 2.2 Class B — missing DB busy_timeout

#### [MEDIUM] B — `gpu_worker.py _next_unanalyzed` + `_load_audio_asset`: no `busy_timeout` *(carried from 2026-08-19; extension confirmed 2026-08-28)*

**File:** `analysis/gpu_worker.py` · Lines 159, 204  
**Status:** confirmed present — **unfixed**

Both `_next_unanalyzed` (line 159) and `_load_audio_asset` (line 204) call `sqlite3.connect(db_path)` with no `timeout=` argument (SQLite default: 5 s). When the canonical DB is held by a concurrent pi-storage writer for longer than 5 s, `DatabaseError: database is locked` propagates and aborts the multi-hour GPU analysis loop on what should be transient lock contention.

Previous audit documented `_next_unanalyzed` only; `_load_audio_asset` is the same class at a second call site in the same file.

Compare: `mac_analyze_loop.py push_track_rows` sets `PRAGMA busy_timeout=120000` (fixed 2026-07-17).

**Fix:** `sqlite3.connect(db_path, timeout=120.0)` in both `_next_unanalyzed` and `_load_audio_asset`.

### 2.3 Class C — silent-failure loops / honest exit codes

#### [HIGH] C — `mac_analyze_sets.py`: unhandled `CalledProcessError` terminates entire batch *(carried from 2026-08-17)*

**File:** `scripts/mac_analyze_sets.py` · Lines 188–234  
**Status:** confirmed present — **unfixed**

```python
for asset in pending:
    rsync_in(asset.path, local_audio)    # CalledProcessError → unwinds loop
    ...
    rsync_stems_out(local_set_dir, sid)  # CalledProcessError → unwinds loop
    push_set_rows(r, local_audio)        # CalledProcessError → unwinds loop
```

Any subprocess failure abandons all remaining sets. No per-set try/except, no quarantine, no nonzero exit code, no `exit_status()` call.

**Fix:** Wrap each per-set phase in try/except; continue on failure; track n_done/n_failed; call `exit_status()` at the end.

**File:** `ingest/main.py` · Lines 614, 617

#### [MEDIUM] C1+C3 — `gpu_worker.py`: `n_done` incremented on failure, always returns 0 *(carried from 2026-07-27)*

**File:** `analysis/gpu_worker.py` · Lines 363–364, 369, 337, 371  
**Status:** confirmed present — **unfixed**

`n_done` is incremented on both success (line 369) and failure (line 364) paths; both loop exit points return `0` unconditionally (lines 337, 371). A run where every track fails logs "done" and returns 0. `--max-tracks N` is exhausted by consecutive failures without any successful analysis.

**Fix:** Track a separate `n_failed` counter; increment only the appropriate counter per outcome; call `exit_status(n_done, n_failed)` at both return sites.

---

#### [MEDIUM] C3 — `mac_analyze_loop.py _persist_in_bg`: `TimeoutExpired` + `sqlite3.Error` escape *(carried from 2026-07-24)*

**File:** `scripts/mac_analyze_loop.py` · Lines ~419–421  
**Status:** confirmed present — **unfixed**

`_persist_in_bg` catches only `subprocess.CalledProcessError`. Two sibling exception classes escape silently, causing the background thread to die without calling `persist_failed_inc()`:

- `subprocess.TimeoutExpired` — fires when `RSYNC_TIMEOUT=600s` or `SSH_PUSH_TIMEOUT=300s` triggers.
- `sqlite3.OperationalError` / `sqlite3.DatabaseError` — raised by raw sqlite3 calls in `push_track_rows`.

Data is not lost (track re-enters the queue), but the honest-count guarantee (C3) is violated.

**Fix:** Widen to `except (subprocess.CalledProcessError, subprocess.TimeoutExpired, sqlite3.Error) as e:` or `except Exception`.
