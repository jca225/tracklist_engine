## 3. Open findings

### 3.1 HIGH (new) · B1/C2 — `mac_analyze_loop.py:517` outer except misses `subprocess.TimeoutExpired`

**File:** `scripts/mac_analyze_loop.py` · Lines ~445–523

**Class:** B1 (missing timeout coverage) + C2 (incorrect transient handling)

The outer `try`/`except` in `main()` that covers the pull→analyze→hand-off
sequence catches only `subprocess.CalledProcessError`:

```python
except subprocess.CalledProcessError as e:
    # Pull/ssh failures reaching here are transient (timeout, broken
    # pipe) — retry with backoff before quarantining (C2).
    if register_transient(tid, str(e), attempts, failed_tids, counts, log):
```

`rsync_in` (line 447) calls `subprocess.check_call(..., timeout=RSYNC_TIMEOUT)`.
When a Tailscale connection stalls for the full `RSYNC_TIMEOUT=600s`,
`subprocess.check_call` raises **`subprocess.TimeoutExpired`**, which is NOT a
subclass of `CalledProcessError` — it is a sibling under `SubprocessError`:

```
subprocess.SubprocessError
  ├── subprocess.CalledProcessError  ← caught
  └── subprocess.TimeoutExpired      ← NOT caught
```

Consequence: a 600s+ Tailscale stall causes `TimeoutExpired` to propagate
uncaught out of `main()`, **crashing the entire analysis loop**. The `finally`
block runs (local file cleanup is fine), but the multi-hour session terminates
rather than retrying with backoff. The comment explicitly names "timeout" as a
case being handled — the intent is correct, the clause is wrong.

**Fix:** widen the catch to `subprocess.SubprocessError` (covers both
`CalledProcessError` and `TimeoutExpired`), or add a second except clause:
```python
except (subprocess.CalledProcessError, subprocess.TimeoutExpired) as e:
```

**Confirmed present** — `TimeoutExpired` is not `CalledProcessError`
(verified: `issubclass(TimeoutExpired, CalledProcessError)` → `False`).

### 3.3 LOW (escalated) · C3 — `mac_analyze_loop.py _persist_in_bg` catches only `CalledProcessError`

**File:** `scripts/mac_analyze_loop.py` · Lines ~409–424

Carried from 2026-07-27 audit (finding 3.4), now **escalated** — the prior
report only noted `OSError`/`sqlite3.OperationalError` escaping; this audit
confirms `subprocess.TimeoutExpired` also escapes for the same reason:

```python
def _persist_in_bg(tid: int, stem_local: Path) -> None:
    try:
        rsync_stems_out(stem_local, tid)   # check_call — can raise TimeoutExpired
        push_track_rows(tid)                # check_call / run(check=True) — same
        counts.done_inc()
    except subprocess.CalledProcessError as e:  # ← misses TimeoutExpired
        counts.persist_failed_inc()
        log.error("[%d] (bg) push failed: %s", tid, e)
```

A timeout on the background stems push or canonical row push escapes the handler.
`counts.persist_failed_inc()` is not called. The thread dies silently; the
main loop joins it normally (dead threads join), then calls `next_task` which
re-picks the same track (no `track_analysis` row landed). This creates a
silent infinite retry loop on a persistently stalled connection. Same fix as
3.1: widen to `subprocess.SubprocessError`.

### 3.4 LOW (carried) · B — `mac_analyze_loop.py:454` sha256 check missing `OSError` guard

**File:** `scripts/mac_analyze_loop.py` · Lines ~454–463

Carried from 2026-07-27 audit (finding 3.2). Still unresolved:

```python
if asset.sha256:
    local_sha = sha256_file(local_audio)   # no try/except OSError
```

An `OSError` here (rsync exits 0 but file is inaccessible) would propagate as
uncaught through the main loop's outer `except CalledProcessError` (which won't
catch `OSError`) and crash the loop. Low probability but easy one-liner fix:

```python
try:
    local_sha = sha256_file(local_audio)
except OSError as exc:
    local_sha = f"<unreadable: {exc}>"
```
