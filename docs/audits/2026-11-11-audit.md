## 3. Semantic Bug Findings

### Class C — Silent-failure loops

---

#### [HIGH] C2a: `mac_analyze_loop._persist_in_bg` swallows `subprocess.TimeoutExpired`

**File:** `scripts/mac_analyze_loop.py:419`  
**Status:** Confirmed present  
**Grade:** High

```python
def _persist_in_bg(tid: int, stem_local: Path) -> None:
    try:
        ...
        rsync_stems_out(stem_local, tid)   # can raise TimeoutExpired
        push_track_rows(tid)               # can raise TimeoutExpired
        counts.done_inc()
    except subprocess.CalledProcessError as e:   # ← only catches CalledProcessError
        counts.persist_failed_inc()
        log.error("[%d] (bg) push failed: %s", tid, e)
    finally:
        shutil.rmtree(stem_local, ignore_errors=True)
```

`rsync_stems_out` and `push_track_rows` both call `subprocess.check_call` / `subprocess.run(check=True)` with explicit `timeout=RSYNC_TIMEOUT` and `timeout=SSH_PUSH_TIMEOUT`. When those timeouts fire, Python raises `subprocess.TimeoutExpired`, which is **not** a subclass of `subprocess.CalledProcessError` and therefore escapes the except clause uncaught.

**Impact sequence:**
1. Thread terminates without calling `counts.done_inc()` or `counts.persist_failed_inc()`
2. The stem directory is cleaned up (finally block) — the analysis work is irrecoverably lost
3. The corresponding `SCRATCH_DB` rows are never pushed to canonical
4. The main loop's `bg.join()` returns normally (thread terminated, not hung)
5. At drain, `exit_status(done=0, failed=0, pf=0)` returns code 0 and INFO "drained" — reads as a clean run

A Tailscale SOCKS stall killing an rsync after 600s is a realistic trigger on the current infrastructure.

**Fix:** Broaden the except clause:
```python
except (subprocess.CalledProcessError, subprocess.TimeoutExpired) as e:
```

#### [MEDIUM] C1: `gpu_worker.py` loop mode always exits 0 regardless of failure ratio

**File:** `analysis/gpu_worker.py:331-337`  
**Status:** Latent  
**Grade:** Medium

```python
if nxt.value is None:
    _log.info(
        "no unanalyzed tracks remain — done (processed %d, quarantined %d)",
        n_done, len(failed_tids),
    )
    return 0   # ← always 0, even when len(failed_tids) == n_done
```

The `exit_status()` function in `loop_hardening.py` exists specifically to escalate the exit code when "nothing succeeded" or "failure ratio > 50%". `mac_analyze_loop.py` uses it. `gpu_worker.py` does not import or call it.

**Impact:** An orchestrator checking `gpu_worker`'s exit code on a 100%-failed run sees 0 (success). The log message contains the quarantine count, but the exit code is what automated pipelines gate on.

**Note:** `gpu_worker` is primarily used in single-track mode from `gpubox_agentic_both.py`; the loop mode (`--loop`) is a secondary code path, so the blast radius is smaller.

**Fix:** Import and use `exit_status()` from `loop_hardening` in the loop drain path.

### Class A — Encoding / mojibake

---

#### [LOW] A1: `ingest` subprocess calls — `text=True` without explicit encoding (8 instances)

**Files:**
- `ingest/adapters/spotdl_adapter.py:99,232`
- `ingest/adapters/ytmusic_adapter.py:216`
- `ingest/adapters/fingerprint.py:65`
- `ingest/stem_guard_runner.py:36`

**Status:** Latent  
**Grade:** Low

These are the 8 `net_subprocess_no_encoding` instances the entropy fence counts. All use `text=True` without `encoding="utf-8"`. On Mac (UTF-8 locale) this is harmless. On pi-storage (aarch64 Linux with an uncertain default locale), a non-ASCII byte in a track name appearing in subprocess stdout/stderr could mojibake into `DownloadError.detail`.

**Mitigating factors:**
- `spotdl_adapter`, `ytmusic_adapter`, and `stem_guard_runner` use the output only for error message strings (never parsed for structured data)
- `fingerprint.py` parses JSON output from `fpcalc`, but `fpcalc -json` output contains only numbers (duration float + fingerprint uint32 array) — no string fields with non-ASCII
- Mojibake here lands in `DownloadError.detail` stored in logs, not in canonical DB paths

**Fix when convenient:** Add `encoding="utf-8", errors="replace"` to all 8 calls (consistent with `loop_hardening.py TEXT_KW` pattern). Not urgent.
