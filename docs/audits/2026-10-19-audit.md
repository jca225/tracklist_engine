## 3. Open findings (carried from 2026-07-27)

### 3.1 MEDIUM (carried) · C1+C3 — `gpu_worker.py` `n_done`/`return 0`

**File:** `analysis/gpu_worker.py` · Lines 359–372

The loop-mode path increments `n_done` on both success and failure:

```python
r = _process_one(a, args.db, ar2.value, resolved, args.stems_dir)
if not r.is_ok():
    failed_tids.add(track_audio_id)
    n_done += 1          # ← C3: bumped on failure
    continue
n_done += 1              # ← success path

# …
_log.info("no unanalyzed tracks remain — done …")
return 0                 # ← C1: queue-drained path always exits 0

# …
_log.info("hit --max-tracks=%d, stopping", …)
return 0                 # ← C1: max-tracks path always exits 0
```

No `n_failed` counter, no `exit_status()` call (contrast `mac_analyze_loop.py`
which calls `exit_status(done, failed, pf)` at both terminal sites). A session
where every track fails returns exit 0; `--max-tracks=N` exhausts against
failures without analyzing anything.

**Fix:** rename the failure-path increment to `n_failed`, call
`exit_status(n_done, n_failed)` at both `return` sites, import it from
`loop_hardening`.

### 3.4 LOW (carried) · C3 — `mac_analyze_loop.py _persist_in_bg` exception scope too narrow

**File:** `scripts/mac_analyze_loop.py` · Lines 409–421

`_persist_in_bg` only catches `subprocess.CalledProcessError`:

```python
try:
    rsync_stems_out(stem_local, tid)
    push_track_rows(tid)
    counts.done_inc()
except subprocess.CalledProcessError as e:
    counts.persist_failed_inc()
```

An `OSError` (scratch DB path missing) or `sqlite3.OperationalError` (lock
timeout on scratch write) would terminate the background thread silently
without calling `persist_failed_inc()` — the Counts tally would undercount
failures.
