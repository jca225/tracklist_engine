### 3.1 MEDIUM (carried) · C1+C3 — `gpu_worker.py` increments `n_done` on failure, always `return 0`

**File:** `analysis/gpu_worker.py` · Lines ~359–372  
**Status:** Carried from 2026-07-27 finding 3.1 — still unresolved.

`n_done` advances on both success and failure paths, and both terminal
conditions (`queue drained`, `--max-tracks`) return `0` unconditionally:

```python
if not r.is_ok():
    ...
    failed_tids.add(track_audio_id)
    n_done += 1          # ← C3: done counter advanced on failure
    continue
...
n_done += 1
# both exits:
return 0                 # ← C1: always success regardless of failure ratio
```

A session where every track fails logs "done" and exits 0 — CI/cron treats
it as success. `mac_analyze_loop.py` already calls `exit_status(done, failed)`
from `loop_hardening`; `gpu_worker.py` should too.

**Fix:** increment a separate `n_failed` counter on the failure path; call
`exit_status(n_done, n_failed)` at both return sites.

### 3.2 MEDIUM (new) · C1+C2 — `_persist_in_bg` catches only `CalledProcessError`, missing `TimeoutExpired`

**File:** `scripts/mac_analyze_loop.py` · Lines ~409–424

The background persist thread catches only `subprocess.CalledProcessError`:

```python
def _persist_in_bg(tid: int, stem_local: Path) -> None:
    try:
        if stem_local.exists():
            rsync_stems_out(stem_local, tid)   # check_call with timeout=RSYNC_TIMEOUT
        push_track_rows(tid)                   # subprocess.run with timeout=SSH_PUSH_TIMEOUT
        counts.done_inc()
    except subprocess.CalledProcessError as e:
        counts.persist_failed_inc()
        log.error(...)
    finally:
        shutil.rmtree(stem_local, ...)
```

`subprocess.TimeoutExpired` is a sibling of `CalledProcessError` (both extend
`SubprocessError`), not a subclass. When the wall-clock deadline fires on
`rsync_stems_out` (two `check_call` calls) or `push_track_rows` (one `run`
call), `TimeoutExpired` propagates through the `finally` block and terminates
the thread. Python's threading machinery does not re-raise this in the main
thread; `bg.join()` returns normally. Results:

- `persist_failed_inc()` is never called — `counts` underreports the failure.
- `done_inc()` is never called — the track is not counted as finished.
- Scratch DB rows for that track are left orphaned (not cleaned by
  `push_track_rows` which didn't complete).
- On the next loop iteration `next_task()` re-selects the same track (its
  `track_analysis` row is still absent from the canonical DB), and the cycle
  repeats indefinitely.

This is latent under normal SSH keepalive conditions because
`loop_hardening.SSH_OPTS` (`ServerAliveInterval=15`, `ServerAliveCountMax=3`)
causes dead connections to die with a non-zero exit (caught as
`CalledProcessError`) before the Python wall-clock deadline fires. It triggers
when a Tailscale SOCKS pipe stalls above the keepalive layer — e.g., a
partial write that keeps a byte flowing but never completes within
`RSYNC_TIMEOUT=600s` or `SSH_PUSH_TIMEOUT=300s`.

Note: the prior audit (2026-07-27 finding 3.4) noted this handler was too
narrow (`OSError`, `sqlite3.OperationalError` were the examples cited).
`TimeoutExpired` is the more impactful missing case since it produces a
silent retry loop rather than a noisy crash.

**Fix:** broaden the except clause:
```python
except (subprocess.CalledProcessError, subprocess.TimeoutExpired) as e:
    counts.persist_failed_inc()
    log.error(...)
```
Or use the common base: `except subprocess.SubprocessError as e:`.

### 3.4 LOW (new) · A2 — `ingest/adapters/ytmusic_adapter.py` and `spotdl_adapter.py` use `text=True` without `encoding=`

**Files:**  
- `ingest/adapters/ytmusic_adapter.py` · Line 216  
- `ingest/adapters/spotdl_adapter.py` · Lines 99, 232

```python
proc = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout_s)
```

On a system whose locale is not UTF-8 (e.g. a pi-storage with a Latin-1
locale, or a Vast box with C/POSIX locale), yt-dlp / spotdl stdout that
contains a non-ASCII track name is decoded with the system default codec
instead of UTF-8. The effect is noisy error logs (mojibake in error detail
strings passed to `DownloadError`), not data corruption, because these paths
only read process output for success/failure classification.

The `loop_hardening.TEXT_KW` constant (`text=True, encoding="utf-8",
errors="surrogateescape"`) exists precisely for this boundary but is not
imported in these adapters.

**Fix:** add `encoding="utf-8", errors="replace"` (or import `TEXT_KW` from
`loop_hardening` and unpack it into the call).
