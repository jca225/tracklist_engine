## 3. Semantic pass — findings graded

Re-reading against issue #8 before grading down-corrected two calls that a
first pass over-inflated. Written up in full so the reasoning is auditable.

### 3.1 LOW (already tracked in #8, 2026-08-14) · B1 — `mac_analyze_loop.py:517` main-loop `except` misses `TimeoutExpired`

**File:** `scripts/mac_analyze_loop.py:517`.

The main-loop try body wraps `rsync_in` (which uses BOTH
`--timeout=RSYNC_IO_TIMEOUT=300s` AND `subprocess.check_call(..., timeout=
RSYNC_TIMEOUT=600s)`). The only way to reach `subprocess.TimeoutExpired`
here is a rsync that keeps making progress but breaches the 600s wall-clock
— rsync's own I/O-idle timeout would otherwise fire first and produce
`CalledProcessError` (properly caught).

Track audio files are ~5–10 MB — a rsync run needs to average <17 KB/s
sustained to breach 600s while never idling long enough to trip the 300s
I/O timeout. Rare in practice, hence LOW; **already listed in issue #8**
with the same reasoning (dated 2026-08-14, still open, not this audit's
find). Fix suggestion (`except subprocess.SubprocessError`) unchanged.
