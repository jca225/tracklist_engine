## 3. Semantic bug audit — new findings

Reasoned over the full in-scope file set looking for class-A/B/C bugs not
already tracked in the rolling issue. **No new Blocker or High findings.**

Corroborating notes on still-open findings:

### 4.1 / 4.2 (HIGH, C2/C3) — `mac_analyze_loop.py` narrow exception handling

Confirmed present on both call sites:
- Line 419 (`_persist_in_bg`): catches only `CalledProcessError`.
  `subprocess.TimeoutExpired` is **not** a subclass of `CalledProcessError`
  (both inherit `SubprocessError`) — a wall-clock timeout on `rsync_stems_out`
  or `push_track_rows` crashes the background thread with an unhandled
  exception, leaving `counts.persist_failed_inc()` never called and the
  track silently dropped from all accounting.
- Line 517 (main loop): same narrowing; a timeout on `rsync_in` or
  `ssh_pi` inside the `try` block propagates out of the loop entirely
  rather than registering a transient failure.

### 3.9 / 3.10 (Medium, C1) — ingest downloader exits 0 unconditionally

Both `ingest/main.py` (line 617) and `ingest/main_retry.py` (line 417)
return 0 at all terminal conditions. `ingest/main.py` additionally has no
`db_failed` field in `RunStats` — DB failures are logged as `_log.error` but
not counted and do not influence the exit code.

### 3.7 (HIGH, A2) — `spotdl_adapter.py` mojibake on non-ASCII track names

Lines 99 and 232 both call `subprocess.run(..., text=True)` without
`encoding=` / `errors=`. On pi-storage (Latin-1 locale) a track name
containing non-ASCII bytes raises an uncaught `UnicodeDecodeError` rather
than round-tripping via `surrogateescape`. The `loop_hardening.TEXT_KW`
pattern (`text=True, encoding="utf-8", errors="surrogateescape"`) should be
applied here.
