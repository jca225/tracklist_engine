## 3. Open findings (all carried from 2026-09-30)

### 3.1 BLOCKER · C — `mac_analyze_loop.py` main loop swallows `TimeoutExpired`

**File:** `scripts/mac_analyze_loop.py` · Line ~517

**Class:** C (silent-failure loop) — uncaught `TimeoutExpired`.

The outer `while True` loop catches only `subprocess.CalledProcessError`.
`rsync_in` calls `subprocess.check_call(timeout=RSYNC_TIMEOUT)`, which raises
`subprocess.TimeoutExpired` (not a subclass of `CalledProcessError`) on a
stalled pull. This exception propagates unhandled, terminating the entire loop
process rather than quarantining the one bad track.

**Fix:** Widen the catch to `except subprocess.SubprocessError`.

---

### 3.2 HIGH · C — `mac_analyze_loop.py _persist_in_bg` misses `TimeoutExpired`

**File:** `scripts/mac_analyze_loop.py` · Lines 409–424

**Class:** C (silent-failure loop) — same class as 3.1 but in the background
persist thread.

`_persist_in_bg` catches only `subprocess.CalledProcessError`. A timeout from
`rsync_stems_out` raises `TimeoutExpired`, which escapes silently:
`persist_failed_inc()` is never called, `failed_tids` is never updated, and the
same track is re-queued on each iteration → infinite silent re-analysis.

**Fix:** Widen to `except (subprocess.SubprocessError, sqlite3.DatabaseError)`.

---

### 3.3 HIGH · A+B — `core/ssh_sqlite.py` no subprocess timeout, no encoding

**File:** `core/ssh_sqlite.py` · Lines 27–34

**Class:** A (encoding) + B (missing timeout).

`subprocess.run` has no `timeout=` — a dead Tailscale peer hangs the process
forever. Also uses `text=True` without `encoding=`; pi-storage runs a Latin-1
locale, so non-ASCII chars in track metadata returned via sqlite3 produce
mojibake or `UnicodeDecodeError`. Missing `ServerAliveInterval`/
`ServerAliveCountMax` in the ssh opts.

**Fix:** Use `loop_hardening.SSH_OPTS`, `SSH_QUERY_TIMEOUT`, and
`encoding="utf-8", errors="surrogateescape"`.

---

### 3.4 MEDIUM · C — `analysis/gpu_worker.py` counts failures as done, always exits 0

**File:** `analysis/gpu_worker.py` · Lines 337, 364, 372

**Class:** C (dishonest exit code + counting).

`n_done` is incremented on both success and failure paths (line 364 on failure).
Both terminal conditions return `return 0` directly instead of calling
`exit_status(n_done, n_failed)`. A GPU run where every track fails logs
"done" and exits 0 — CI/cron treats it as success. With `--max-tracks N`,
N consecutive failures exhaust the limit with zero records written, exit 0.

**Fix:** Track `n_failed` separately; call `exit_status(n_done, n_failed)` at
both return sites (mirrors `mac_analyze_loop.py`'s existing pattern).

### 4.5 MEDIUM · B — `ingest/main_retry.py` batch timeout unbounded at scale

**File:** `ingest/main_retry.py` · Line 256

**Class:** B (missing effective timeout).

```python
batch_timeout = max(args.timeout * 2, (bs / threads) * args.timeout * 2)
```

At `--batch-size=100 --threads=1 --timeout=60` this yields 12 000 s (>3 h)
per batch. A single stalled spotdl process can block the entire batch for hours.

### 4.6 MEDIUM · C — `acquire_variant.py` content gate silently skipped on insert

**File:** `scripts/acquire_variant.py` · Lines 219–241

**Class:** C (silent-failure / gate bypass).

If `_lookup_latest_audio_row` returns `None` after a successful insert, the
content gate is skipped (`cv = ... if row else None`). The newly inserted row
is never quality-checked, and a bad download (preview clip, etc.) passes
through without rejection.

### NEW-1 LOW (new) · B — `mac_analyze_loop.py` rsync calls don't pass `SSH_OPTS`

**File:** `scripts/mac_analyze_loop.py` · Lines ~179, ~199 (`rsync_in`,
`rsync_stems_out`)

**Class:** B (latent — rsync SSH transport missing hardening opts).

Both rsync calls use bare `PI_HOST:path` syntax. The underlying SSH transport
inherits system defaults instead of `loop_hardening.SSH_OPTS`
(`ConnectTimeout=15`, `BatchMode=yes`, keepalive). Without `BatchMode=yes`,
a missing key blocks on a password prompt; without `ConnectTimeout=15`, the
initial handshake stall is not bounded by `rsync --timeout` (which only
triggers mid-transfer). The subprocess `timeout=RSYNC_TIMEOUT` is the only
backstop. Note: the `mkdir` SSH call in `rsync_stems_out` already passes
`*SSH_OPTS` — the rsync itself does not.

**Fix:** Add `-e "ssh {' '.join(SSH_OPTS)}"` to both rsync commands.
