## 4. Carried open findings (all from prior audits, none closed on HEAD)

### 4.1 HIGH · C1 — `analysis/gpu_worker.py` loop exits 0 on all-failure drain

**File:** `analysis/gpu_worker.py` · Lines 331–337, 359–365, 371–372

`n_done` is incremented on both the success **and** failure paths; both exit
sites (`queue drained` and `--max-tracks` hit) call `return 0`
unconditionally. A GPU run where every track fails quarantines them all, then
drains to `return 0` with "no unanalyzed tracks remain". CI / the gpubox
orchestrator reads this as success.

`mac_analyze_loop.py` correctly calls `exit_status(n_done, n_failed)` from
`loop_hardening`; `gpu_worker.py` was not updated to match.

**Fix:** separate `n_failed` from `n_done` on the failure path; call
`exit_status(n_done, n_failed)` at both return sites.

### 4.2 HIGH · A — `ingest/adapters/spotdl_adapter.py` `text=True` without encoding

**File:** `ingest/adapters/spotdl_adapter.py` · Lines 99, 232

```python
proc = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout_s)
```

`text=True` without `encoding=` decodes stdout/stderr with the system default
(Latin-1 on pi-storage). A non-ASCII character in a track name raises
`UnicodeDecodeError`, crashing the spotdl adapter call with an unhandled
exception. `loop_hardening.TEXT_KW` provides the correct pattern
(`encoding="utf-8", errors="surrogateescape"`); spotdl_adapter predates it.

**Fix:** add `encoding="utf-8", errors="replace"` to both `subprocess.run`
calls (or use `TEXT_KW`).

---

### 4.3 HIGH · C2 — `mac_analyze_loop.py` main loop catches only `CalledProcessError`

**File:** `scripts/mac_analyze_loop.py` · Line 517

```python
except subprocess.CalledProcessError as e:
    if register_transient(tid, str(e), ...):
```

The main `while True` loop catches only `CalledProcessError`. When Tailscale
degrades and a Python wall-clock timeout fires (`rsync_in` / `ssh_pi` carry
explicit `timeout=` args), `subprocess.TimeoutExpired` is uncaught and kills
the **entire loop process** — no retry, no graceful drain, requires manual
restart.

**Fix:** widen to `except subprocess.SubprocessError` (covers both
`CalledProcessError` and `TimeoutExpired`); `TimeoutExpired` is already a
transient condition so the existing `register_transient` call handles it
correctly once it's caught.

### 4.4 HIGH · C1 — `ingest/main.py` unconditional `return 0`

**File:** `ingest/main.py` · Lines 614, 617

Both exit sites of `_run()` (`--max-tracks` stop and normal drain) call
`return 0` regardless of how many tracks failed. A full corpus run that
downloads zero tracks exits 0 — the operator's cron sees success.

---

### 4.5 MEDIUM · C3 — `mac_analyze_loop._persist_in_bg` exception scope too narrow

**File:** `scripts/mac_analyze_loop.py` · Lines 419–423

The background persist thread catches only `subprocess.CalledProcessError`.
`subprocess.TimeoutExpired` (SSH push timeout after 300s wall-clock) escapes
as an unhandled thread exception — printed to stderr by Python's thread
handler, not to the application logger — and `counts.persist_failed_inc()` is
never called. The honest tally (C3) is broken for SSH timeout in the bg push,
and the operator has no log evidence the persist failed.

**Fix:** widen to `except subprocess.SubprocessError` (or at least add
`subprocess.TimeoutExpired` to the except clause).

---

**File:** `ingest/main_retry.py` · Line 417
