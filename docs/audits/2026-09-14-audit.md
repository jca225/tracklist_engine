### Class B / C — Subprocess exception hierarchy mismatch (two sites)

#### Finding B1a — **HIGH, confirmed present**
**`mac_analyze_loop.main()` outer loop crashes on `TimeoutExpired`**

- **File:** `scripts/mac_analyze_loop.py:517`
- **Code:**
  ```python
  except subprocess.CalledProcessError as e:
      # Pull/ssh failures reaching here are transient (timeout, broken
      # pipe) — retry with backoff before quarantining (C2).
  ```
- **Bug:** `rsync_in()` (`scripts/mac_analyze_loop.py:171`) and
  `ssh_pi()` (used by `fetch_asset`, line 154) both call subprocess with
  explicit `timeout=` arguments (`RSYNC_TIMEOUT=600`, `SSH_QUERY_TIMEOUT=120`).
  When those wall-clock limits fire, Python raises `subprocess.TimeoutExpired`
  — a sibling of `CalledProcessError` under `SubprocessError`, not a subclass.
  The `except subprocess.CalledProcessError` block does NOT catch
  `TimeoutExpired`. The `finally` block runs (local file cleanup is correct),
  but `TimeoutExpired` then propagates out of the `while True` loop and crashes
  the entire `mac_analyze_loop` process with an unhandled exception.
- **Failure scenario:** Tailscale link degrades while an rsync or DB query is
  in flight. Wall-clock timeout fires → `TimeoutExpired` → process exits with
  uncaught exception → all remaining tracks in the queue are abandoned, requiring
  a manual restart. The comment says "timeout, broken pipe" as intended cases,
  but the code only handles the non-timeout case.
- **Fix:** Widen catch to `subprocess.SubprocessError` (or explicitly add
  `subprocess.TimeoutExpired`) so the existing transient-retry logic handles
  both exit-code failures and wall-clock timeouts.

#### Finding B1b — **MEDIUM, confirmed present**
**`_persist_in_bg` swallows `TimeoutExpired` silently — wrong tally**

- **File:** `scripts/mac_analyze_loop.py:419`
- **Code:**
  ```python
  except subprocess.CalledProcessError as e:
      counts.persist_failed_inc()
      log.error("[%d] (bg) push failed: %s", tid, e)
  ```
- **Bug:** Same exception hierarchy issue in the background persist thread.
  `rsync_stems_out()` and `push_track_rows()` both invoke subprocess with
  timeouts (`RSYNC_TIMEOUT`, `SSH_PUSH_TIMEOUT`, `SSH_QUERY_TIMEOUT`). A
  `TimeoutExpired` is not caught, so the thread exits without calling either
  `counts.done_inc()` or `counts.persist_failed_inc()`. Neither counter
  reflects the lost track; `exit_status()` in the main drain path cannot
  escalate because it sees no persist failure; the track silently vanishes from
  accounting. The `finally` block still removes local stems (correct), so no
  disk leak, but the honest-counting guarantee (C3) is violated.
- **Failure scenario:** Same Tailscale degradation as B1a, but during the
  background push rather than the pull. The main loop survives (it only
  `join()`s the thread), but the track is neither counted done nor failed —
  invisible to `exit_status()`. Over a long run this could mask persistent
  push timeouts.
- **Fix:** Widen the catch in `_persist_in_bg` to `subprocess.SubprocessError`
  (or add `subprocess.TimeoutExpired`), mirroring the B1a fix.

### Class A — Encoding (latent, not new)

#### Finding A1 — **LOW, latent**
**`replace_track_audio._probe_duration_s` uses `text=True` without encoding**

- **File:** `scripts/replace_track_audio.py:640-654`
- **Code:**
  ```python
  out = subprocess.run([ffprobe, ...], capture_output=True, text=True, timeout=30)
  return float(out.stdout.strip()) if out.stdout.strip() else None
  ```
- **Bug:** `text=True` without `encoding=` uses the system locale's default
  codec. ffprobe output for `-show_entries format=duration` is `"234.567000\n"` —
  pure ASCII — so this never triggers in practice. The risk is if error text
  bleeds to stdout on a system with a non-UTF-8 locale and ffprobe prints a
  non-ASCII path in its output.
- **Grade:** Low, latent. The `except (subprocess.SubprocessError, ValueError)`
  catch absorbs decode errors correctly, so even if it misfires the function
  returns `None` and the gate passes (conservative). Not actionable this cycle.
