## 3. Open findings

### 3.1 BLOCKER · C — `mac_analyze_loop.py` main loop crashes on `subprocess.TimeoutExpired`

**File:** `scripts/mac_analyze_loop.py` · Lines ~447, ~517  **Status:** confirmed present

`rsync_in` calls `subprocess.check_call(..., timeout=RSYNC_TIMEOUT)`. A
600 s wall-clock overrun raises `subprocess.TimeoutExpired`, which is NOT a
subclass of `subprocess.CalledProcessError` — it is a sibling (both inherit
from `subprocess.SubprocessError`). Both exception handlers in the analysis
loop catch only `CalledProcessError`:

```python
except subprocess.CalledProcessError as e:
    if register_transient(tid, str(e), attempts, failed_tids, counts, log):
        ...
```

A `TimeoutExpired` propagates past the `finally` block and out of the `while
True` loop, crashing the entire process. The operator must manually restart; any
in-progress background threads are abandoned. The same gap exists at line ~517
in the set-analysis branch.

**Fix:** change both `except subprocess.CalledProcessError` to
`except subprocess.SubprocessError` (covers `CalledProcessError`,
`TimeoutExpired`, and `ProcessLookupError`). Both are transient — feed them to
`register_transient`.

### 3.2 HIGH · C — `mac_analyze_loop.py _persist_in_bg` swallows `TimeoutExpired`, enables infinite re-queue

**File:** `scripts/mac_analyze_loop.py` · Lines 409–424  **Status:** confirmed present

```python
def _persist_in_bg(tid: int, stem_local: Path) -> None:
    try:
        ...
        rsync_stems_out(stem_local, tid)   # uses check_call(timeout=RSYNC_TIMEOUT)
        push_track_rows(tid)               # subprocess ssh with SSH_PUSH_TIMEOUT
        counts.done_inc()
    except subprocess.CalledProcessError as e:
        counts.persist_failed_inc()
        log.error("[%d] (bg) push failed: %s", tid, e)
```

`rsync_stems_out` calls `check_call(..., timeout=RSYNC_TIMEOUT)`. A timeout
raises `TimeoutExpired` which the `except CalledProcessError` does not catch.
The thread dies silently without calling either `done_inc()` or
`persist_failed_inc()`. The Counts tally undercounts failures and `exit_status()`
may report success. Worse: the track was never pushed to canonical, so
`_next_unanalyzed` re-selects it on the next iteration — the same track is
re-analyzed indefinitely until the process is killed.

**Fix:** widen to `except subprocess.SubprocessError` and additionally catch
`sqlite3.DatabaseError` (from the scratch DB writes inside `push_track_rows`).

### 3.3 HIGH · B — `core/ssh_sqlite.py` missing subprocess timeout and `ServerAliveInterval`

**File:** `core/ssh_sqlite.py` · Lines 27–34  **Status:** confirmed present

```python
cmd = ["ssh", "-o", "ConnectTimeout=15", host, f"sqlite3 {db}"]
out = subprocess.run(
    cmd,
    input=script,
    capture_output=True,
    text=True,
    check=True,
)
```

Two gaps:
1. **No `timeout=`** — `ConnectTimeout=15` only covers the TCP handshake. Once
   the connection is up, a dead Tailscale peer (routing loop, silent disconnect)
   hangs the call indefinitely. `loop_hardening.SSH_OPTS` adds
   `ServerAliveInterval=15`/`ServerAliveCountMax=3` (detects post-connect silence
   in ~45 s) AND callers pass `timeout=SSH_QUERY_TIMEOUT` (120 s hard wall-clock).
2. **Missing encoding** — `text=True` without `encoding="utf-8"` uses the
   system locale. On pi-storage (Latin-1 default), non-ASCII characters in
   results (track titles, artist names) are decoded with Latin-1 and produce
   mojibake strings. This is the same family (A2/B1) that motivated
   `loop_hardening.TEXT_KW`.

**Fix:** replace the ad-hoc opts list with `loop_hardening.SSH_OPTS`, add
`timeout=loop_hardening.SSH_QUERY_TIMEOUT`, and replace `text=True` with
`**loop_hardening.TEXT_KW`.

### 3.4 MEDIUM (carried) · C — `gpu_worker.py` increments `n_done` on failure, always returns 0

**File:** `analysis/gpu_worker.py` · Lines 358–372  **Status:** confirmed present (unchanged since 2026-07-27)

`n_done` is advanced on both the failure path (line 364) and success path (line
369). Both exit paths `return 0`. A session where every track fails returns 0;
`--max-tracks N` is exhausted by failures with no rows written.

**Fix:** separate `n_done` (successes) from `n_failed`; call
`exit_status(n_done, n_failed)` at both return sites (lines 337, 372).

### 3.5 MEDIUM · C — `ingest/main.py` always returns 0

**File:** `ingest/main.py` · Lines 613–617  **Status:** confirmed present

The two terminal cases (max-tracks hit and queue drained) both `return 0`
regardless of failure count. A run where every track failed bot-detection or
network error exits 0 — CI/monitoring receives no signal.

**Fix:** compute a failure ratio in `_summarize` and return nonzero when
`stats.downloaded == 0` or failure ratio exceeds a threshold, using the same
`exit_status` pattern as `mac_analyze_loop.py`.

### 3.6 MEDIUM · C — `ingest/main_retry.py` always returns 0

**File:** `ingest/main_retry.py` · Line 417  **Status:** confirmed present

The full `_run()` function returns 0 after logging stats. A batch where all 174
spotdl candidates timed out (documented in the header comment) logs
`downloaded=0 timeout=174` and returns 0.

**Fix:** return 1 (or call `exit_status()`) when `stats.downloaded == 0` and
`stats.candidates > 0`.

### 3.7 LOW (carried) · B — `mac_analyze_loop.py` sha256 check missing `OSError` guard

**File:** `scripts/mac_analyze_loop.py` · Line 455  **Status:** confirmed present

```python
if asset.sha256:
    local_sha = sha256_file(local_audio)   # no try/except OSError
```
