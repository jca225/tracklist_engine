## 2. New findings

### 2.1 HIGH · B1+A2 — `mac_analyze_sets.py` SSH/rsync calls: no timeout, no encoding

**File:** `scripts/mac_analyze_sets.py` · Lines ~87–104, ~148

**Classes:** B1 (missing subprocess timeout), A2 (text=True without encoding at
SSH/pi boundary).

Four subprocess call sites in this set-analysis driver import nothing from
`loop_hardening.py` and carry none of the hardening primitives:

```python
# ssh_pi() — the sqlite3 query helper
subprocess.run(["ssh", PI_HOST, full],
               capture_output=True, text=True, check=True)   # no timeout, no encoding

# rsync_in() — pulls set audio from pi-storage
subprocess.check_call(["rsync", "-q", f"{PI_HOST}:{remote_path}", str(local)])  # no timeout

# rsync_stems_out() — two calls: ssh mkdir + rsync push
subprocess.check_call(["ssh", PI_HOST, f"mkdir -p ..."])               # no timeout
subprocess.check_call(["rsync", "-aq", src, dst])                      # no timeout

# push_to_pi() — canonical row write (~line 148)
subprocess.run(["ssh", PI_HOST, f"sqlite3 {CANONICAL_DB}"],
               input=full, text=True, check=True)            # no timeout, no encoding
```

A dead Tailscale connection causes all four call sites to wedge indefinitely.
The `text=True` without `encoding=utf-8, errors=surrogateescape` is the
mojibake path that `loop_hardening.py:TEXT_KW` was created to fix; a pi-storage
path containing a Latin-1 byte would corrupt the row on write.

The script also uses bare `["ssh", PI_HOST, ...]` without `SSH_OPTS`, so
keepalive (`ServerAliveInterval/CountMax`) and `BatchMode=yes` are missing —
a dead connection won't be detected for the OS-default TCP timeout (minutes).

**Fix:** import `SSH_OPTS`, `SSH_QUERY_TIMEOUT`, `SSH_PUSH_TIMEOUT`,
`RSYNC_TIMEOUT`, `RSYNC_IO_TIMEOUT`, `TEXT_KW` from `loop_hardening` and
apply them, matching the `mac_analyze_loop.py` pattern.

**Status:** confirmed present.

**Status:** confirmed present.
