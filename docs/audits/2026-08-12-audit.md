### Class B — Missing subprocess/rsync timeouts; no-integrity-check transfers

#### [LOW / latent] B1 — `mac_analyze_loop.py` main loop: `TimeoutExpired` not retried

**File:** `scripts/mac_analyze_loop.py` · Line 517  
**New this audit:** Yes (the existing issue tracks the `_persist_in_bg` escape
path; the main loop is a distinct manifestation with a different consequence.)

```python
except subprocess.CalledProcessError as e:
    # ... register_transient / backoff
```

`subprocess.TimeoutExpired` is a sibling of `CalledProcessError` (both inherit
from `SubprocessError`) and is NOT caught here. If `rsync_in` (wall-clock 600s)
or `ssh_pi` (wall-clock 120s) raises `TimeoutExpired`, the exception propagates
past the `except` clause, through the `finally` cleanup, and terminates the
entire analysis loop process.

**Practical severity:** Low/latent. `rsync --timeout=300` (the I/O-stall timer)
fires first and exits rsync with a non-zero code (`CalledProcessError`) — the
wall-clock 600s timeout only triggers when rsync is making slow but non-zero
progress and doesn't fully stall. Similarly, `SSH_OPTS` keepalive probes (15s ×
3) cause SSH to exit non-zero before the 120s wall-clock fires. In practice this
requires a degraded Tailscale tunnel that transfers bytes at >0 but very slowly.

**Fix:** Widen the main loop except to `except (subprocess.CalledProcessError,
subprocess.TimeoutExpired)` so the same `register_transient` logic applies.

#### [MEDIUM → HIGH / confirmed present] C1+C3 — `gpu_worker.py --loop` always returns 0; `n_done` bumped on failure

Confirmed present. Line 337 returns 0 on drain; line 364 increments `n_done` on

First noted 2026-07-27; no fix on main as of this audit.

#### [MEDIUM / confirmed present] C3 — `mac_analyze_loop._persist_in_bg`: `TimeoutExpired` and `sqlite3.Error` escape

Confirmed present. The `_persist_in_bg` background thread (lines ~409–424) only
catches `subprocess.CalledProcessError`. Two classes escape:

- **`subprocess.TimeoutExpired`** — fires when `SSH_PUSH_TIMEOUT=300s` or
  `RSYNC_TIMEOUT=600s` triggers in the bg thread (e.g., a slow Tailscale
  tunnel). Not a subclass of `CalledProcessError`.
- **`sqlite3.OperationalError` / `sqlite3.DatabaseError`** — `push_track_rows`
  directly calls `_sqlite3.connect().execute().commit()` (lines 242, 261, 324).
  These raise `sqlite3.Error`, which is also not a subclass of
  `CalledProcessError`.

When either escapes: `persist_failed_inc()` is never called; `exit_status()`
underreports failures. The track re-enters the queue on the next run (no
`track_analysis` row written), so data is not permanently lost — but the C3
honest-count guarantee is violated.

First noted as TimeoutExpired 2026-07-24, sqlite3.Error confirmed 2026-08-03. No
fix on main as of this audit.

**Fix:** Widen to `except (subprocess.CalledProcessError, subprocess.TimeoutExpired,
sqlite3.Error) as e:` — or `except Exception` with `log.exception`.

#### [MEDIUM / confirmed present] C1 — `ingest/main_retry.py` always returns 0

Confirmed present. Line 417 `return 0` unconditionally regardless of
`stats.downloaded`. A spotdl retry session with 100% timeouts exits 0. First
noted 2026-08-05; no fix on main as of this audit.

#### [LOW / confirmed present] B — `mac_analyze_loop.py`: `sha256_file` without `OSError` guard

Confirmed present. `sha256_file(local_audio)` at lines ~454–456 is called without
`try/except OSError`. An `OSError` (file vanished between rsync and the hash
call, e.g. on a low-storage Mac) propagates past the main loop's
`except CalledProcessError` and crashes the loop. First noted 2026-07-24; no fix
on main as of this audit.
