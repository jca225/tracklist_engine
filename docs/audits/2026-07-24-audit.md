## New Findings

### HIGH — vast_worker.py: wrong table for set-scope filtering

**File:** `analysis/vast_worker.py`, function `_next_unanalyzed()`, lines ~154–190  
**Class:** C2 (silent scope error / wrong queue predicate)

`_next_unanalyzed()` filters tracks to a set scope using `dj_set_track_media_links`:

```sql
AND ta.track_id IN (
    SELECT DISTINCT track_id FROM dj_set_track_media_links
    WHERE set_id IN ({placeholders})
)
```

`dj_set_track_media_links` is the scraper's raw media-link table. The canonical per-set track spine is `set_track_slots`, which includes gap rows — tracks with manually-ingested audio that carry no scraped media link. `vast_loop.py` (the production path) documents this at lines 126–132 and uses `set_track_slots`.

**Impact:** When `--bb-only` or an explicit `--set-ids` scope is used, `vast_worker.py` silently skips all gap rows (14 confirmed in BB11, unknown count in other sets). Those tracks never get analyzed under a set-scoped run. Corpus-wide `--all` runs are unaffected — the set filter is not applied.

**Fix:** Replace `dj_set_track_media_links` with `set_track_slots` for the set-scoping subquery, matching the pattern in `vast_loop.py:126–132`.

### MEDIUM — fetch_measure_times: json.loads on potentially empty output

**Files:** `scripts/mert_backfill_loop.py:127`, `scripts/set_mert_backfill_loop.py:114`  
**Class:** C3 (unhandled exception → script crash)

```python
def fetch_measure_times(track_audio_id: int) -> tuple[float, ...]:
    sql = ("SELECT measure_times_json FROM track_analysis ...")
    out = ssh_pi(sql)
    times = json.loads(out)   # JSONDecodeError if out is "" or "NULL"
    return tuple(float(t) for t in times)
```

If `measure_times_json` is NULL in the DB (track queued before analysis ran, or a partial row), `ssh_pi()` returns `""`. `json.loads("")` raises `json.JSONDecodeError`, which is **not** caught by the surrounding `except subprocess.CalledProcessError` in the main loop — the exception propagates and crashes the entire backfill script, abandoning all remaining work.

**Fix:** Guard with `if not out: raise ValueError(f"empty measure_times for id={...}")` before `json.loads` (or wrap in `try/except json.JSONDecodeError`), then add to `failed` in the main loop so the track is skipped without crashing.

### LOW — mac_analyze_loop.py: sha256_file without OSError guard

**File:** `scripts/mac_analyze_loop.py`, lines ~454–457  
**Class:** B2 (integrity check gap)

```python
if asset.sha256:
    local_sha = sha256_file(local_audio)   # no try-except around OSError
    if local_sha != asset.sha256:
```

`vast_loop.py:638–641` wraps the identical call:

```python
try:
    local_sha = sha256_file(local_audio)
except OSError as exc:
    local_sha = f"<unreadable: {exc}>"
```

If the just-rsynced file is unreadable (permissions failure, fs error, partial write not caught by rsync), `sha256_file` raises `OSError`. This is **not** caught by the outer `except subprocess.CalledProcessError`, propagates as an unhandled exception, and terminates the mac loop rather than logging a warning and continuing to the next track.

**Fix:** Add the same `try/except OSError` guard as `vast_loop.py`.

### LOW — MERT backfill loops: no register_transient (carried from 2026-07-22)

**Files:** `scripts/mert_backfill_loop.py`, `scripts/set_mert_backfill_loop.py`  
**Class:** C2 (poison-pill quarantine too aggressive)

Neither script imports `register_transient`. Any `subprocess.CalledProcessError` (rsync network blip, SSH hiccup) immediately adds the track/set to `failed` and permanently skips it for the rest of the session. A transient network error on track 1 of a 500-track run causes that track to be silently dropped rather than retried.

`vast_loop.py` uses `register_transient()` with a bounded backoff to distinguish transient failures from permanent poison pills.

**Fix:** Import `register_transient` from `loop_hardening` and use it for rsync/SSH errors, consistent with `vast_loop.py`.

---

### LOW — Background tail threads: narrow exception catch

**Files:** `scripts/vast_loop.py` (`_finish_in_bg`), `scripts/mac_analyze_loop.py` (`_persist_in_bg`)  
**Class:** C3 (silent failure in background thread)

The background threads that handle canonical push while the next track analyzes only catch `subprocess.CalledProcessError`:

```python
except subprocess.CalledProcessError as e:
    log.error(...)
    # n_failed not incremented; thread exits silently
```

A non-subprocess exception (`sqlite3.OperationalError`, `OSError` on the local file, `json.JSONDecodeError`) silently kills the thread — no log entry, no count update, no retry. The track is counted as done (`n_done` was incremented at handoff to the thread) while canonical never received its rows.

**Fix:** Broaden the catch to `Exception` with `log.exception` and either decrement `n_done` / increment `n_failed`, or propagate failures back to the main loop via a thread-safe queue.
