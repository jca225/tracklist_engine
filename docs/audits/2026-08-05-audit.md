## 3. Open findings

### 3.1 HIGH (new) · C1 — `ingest/main.py` always exits 0

**File:** `ingest/main.py` · Lines 613–617  
**Class:** C1 — dishonest exit code  
**Status:** confirmed present, new finding

`_run()` unconditionally returns `0` at both exit paths:

```python
# hit --max-tracks
_summarize(stats, time.monotonic() - t0)
return 0  # ← regardless of stats.failed_download

# queue drained
_summarize(stats, time.monotonic() - t0)
return 0  # ← even when downloaded=0, failed_download=16000
```

A full-corpus run where every download fails (yt-dlp bot-blocked, no JS runtime,
broken Tailscale) returns exit 0 with a `_summarize()` log line that shows
zero successes but does not alarm any CI/cron/systemd `OnFailure=` policy.
This is the exact class C1 that `loop_hardening.exit_status()` was built to
fix for the analysis loops — `mac_analyze_loop.py` uses it; `ingest.main` does not.

**Fix:** add a failure-ratio check analogous to `loop_hardening.exit_status()`:
if `stats.downloaded == 0 and stats.failed_download > 0`, or if
`stats.failed_download / (stats.downloaded + stats.failed_download) > 0.5`,
return nonzero. Alternatively import `exit_status` and plumb it through
`RunStats`.

### 3.2 MEDIUM (carried) · C1+C3 — `gpu_worker.py`: `n_done` incremented on failure, always returns 0

**File:** `analysis/gpu_worker.py` · Lines ~356–372  
**Carried since:** 2026-07-27 — still unfixed

`n_done` is incremented on both success and failure paths; both exit points return
`0` without calling `exit_status()`.

1. A GPU box run where every track fails exits 0 — CI/cron treats it as success.
2. `--max-tracks N` exhausts after N total attempts (including failures) rather
   than N successes; caller receives exit 0 with no records written.

**Fix:** rename the failure-path increment to `n_failed`; call
`exit_status(n_done, n_failed)` at both return sites (matching the
`mac_analyze_loop.py` pattern from `loop_hardening`).

### 3.3 MEDIUM (carried) · C3 — `mac_analyze_loop._persist_in_bg`: `TimeoutExpired` not caught

**File:** `scripts/mac_analyze_loop.py` · Lines ~409–424  
**Upgraded from LOW:** 2026-08-03 (specific escape path confirmed)  
**Carried since:** 2026-08-03 — still unfixed

`_persist_in_bg` catches only `subprocess.CalledProcessError`. `TimeoutExpired`
is a sibling class and escapes the handler. Both `rsync_stems_out` and
`push_track_rows` carry explicit timeouts (`RSYNC_TIMEOUT=600`,
`SSH_PUSH_TIMEOUT=300`), so a timeout is a plausible production path.
When it occurs, the thread terminates without calling `persist_failed_inc()`
— `exit_status()` gets `n_persist_failed=0` when it should be nonzero.

**Fix:** widen to `except (subprocess.CalledProcessError, subprocess.TimeoutExpired) as e:`.

### 3.4 MEDIUM (new) · C1 — `ingest/main_retry.py` always exits 0

**File:** `ingest/main_retry.py` · Line 417  
**Class:** C1 — dishonest exit code  
**Status:** confirmed present, new finding

`_run()` returns `0` unconditionally after the sequential and batched loops:

```python
elapsed = time.monotonic() - t0
_log.info("DONE | candidates=%d downloaded=%d ...", stats.candidates, ...)
return 0  # ← always
```

A spotdl retry session where every candidate times out (the common path with
bundled default creds — a 24h global rate-limit is documented at line 362)
logs `downloaded=0 timeout=N` and returns 0. Same C1 class as `ingest.main`;
lower severity because spotdl retry is an expected-partial-failure path.

**Fix:** same failure-ratio escalation as 3.1; return nonzero when
`stats.downloaded == 0` and at least one non-unavailable failure occurred
(unavailable = genuinely gone, not a transient failure).

### 3.5 LOW (carried) · B — `mac_analyze_loop.py`: `sha256_file` without `OSError` guard

**File:** `scripts/mac_analyze_loop.py` · Lines ~454–456  
**Carried since:** 2026-07-24

`sha256_file(local_audio)` is called bare inside the `try: ... except
subprocess.CalledProcessError:` block. An `OSError` (disk full, rsync truncated
to 0 and unlinked, race with the `finally:` cleanup) would not be caught
by the CalledProcessError handler and would propagate to the outer `while True:`
— crashing the loop entirely. `set_mert_backfill_loop.py` had the OSError guard
before it was deleted.

**Fix:** `try: local_sha = sha256_file(local_audio) / except OSError as exc: local_sha = f"<unreadable: {exc}>"`.
