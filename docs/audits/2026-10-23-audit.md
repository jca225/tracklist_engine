## 3. Open findings

### 3.1 MEDIUM (carried) · C1+C3 — `gpu_worker.py` returns 0 even when all work failed

**File:** `analysis/gpu_worker.py` · Lines ~326–372

**Status:** Carried from 2026-07-27. Still present, not fixed.

`n_done` is incremented on both success and failure paths, and both loop
terminal conditions (`_next_unanalyzed` returns None, `--max-tracks` reached)
unconditionally return 0:

```python
r = _process_one(a, args.db, ar2.value, resolved, args.stems_dir)
if not r.is_ok():
    _log.warning("FAIL track_audio_id=%s: %s", track_audio_id, r.error)
    failed_tids.add(track_audio_id)
    n_done += 1      # C3: done counter advanced on failure
    continue
...
if nxt.value is None:
    _log.info("no unanalyzed tracks remain — done ...")
    return 0         # C1: always 0, even if n_done=0 and all quarantined
```

A session where every track fails returns exit 0. Compare: `mac_analyze_loop.py`
calls `exit_status(n_done, n_failed)` which escalates to nonzero+ERROR when
`n_done == 0` or failure ratio exceeds 50%.

**Fix:** split `n_done` into `n_ok`/`n_failed`; call `exit_status()` from
`loop_hardening.py` at both return sites. This matches the mac_analyze_loop
contract.

### 3.2 MEDIUM (new) · B1+A2 — `render_set_stems.ssh_pi_sql()` unguarded SSH call

**File:** `scripts/render_set_stems.py` · Lines 63–69

```python
def ssh_pi_sql(sql: str) -> str:
    r = subprocess.run(
        ["ssh", PI_HOST, f'sqlite3 -separator "|" {CANONICAL_DB} "{sql}"'],
        capture_output=True,
        text=True,
        check=True,
    )
    return r.stdout.strip()
```

Three missing guards:

1. **B1 (hang):** No `SSH_OPTS` (no `ConnectTimeout`, `ServerAliveInterval`,
   `BatchMode`) and no subprocess `timeout=`. A dead Tailscale link or
   unresponsive pi-storage hangs `subprocess.run` indefinitely. This script
   is designed for **unattended overnight runs** — a stall at any `ssh_pi_sql`
   call (fetch_set_audio at startup, or the final push) would silently block
   the whole session for hours with no log output.

2. **A2 (encoding):** `text=True` without `encoding="utf-8",
   errors="surrogateescape"`. Any non-ASCII byte in a path returned from
   pi-storage (Latin-1 locale) would raise `UnicodeDecodeError` and abort
   the run. Currently latent (set_audio paths are ASCII), but adds fragility
   at the same SSH/sqlite boundary that burned the main analyze loops.

Compare: `mac_analyze_loop.ssh_pi()` uses all of: `*SSH_OPTS`,
`timeout=SSH_QUERY_TIMEOUT`, `encoding="utf-8"`, `errors="surrogateescape"`.

**Fix:** import `SSH_OPTS`, `SSH_QUERY_TIMEOUT` from `loop_hardening` and apply
to the `subprocess.run` call; add `encoding="utf-8", errors="surrogateescape"`.

### 3.3 LOW (carried) · B — `mac_analyze_loop.py:454` sha256_file missing OSError guard

**File:** `scripts/mac_analyze_loop.py` · Lines ~454–463

**Status:** Carried from 2026-07-27. Still present.

```python
if asset.sha256:
    local_sha = sha256_file(local_audio)   # no try/except OSError
```

If rsync exits 0 but the file is unreadable (permissions, truncated link), the
`OSError` propagates uncaught out of the main loop body. The `finally` block does
clean up `local_audio`, but `counts.persist_failed_inc()` is never called, so
the tally undercounts failures. Low probability (rsync truncation typically fails
with nonzero), but inconsistent with `set_mert_backfill_loop` (now removed) which
had the guard.

### 3.4 LOW (carried) · C3 — `mac_analyze_loop._persist_in_bg` narrow except

**File:** `scripts/mac_analyze_loop.py` · Lines ~409–424

**Status:** Carried from 2026-07-27. Still present.

`_persist_in_bg` only catches `subprocess.CalledProcessError`. An `OSError`
(scratch DB path missing) or `sqlite3.OperationalError` (lock timeout) would
silently terminate the background thread without calling `persist_failed_inc()`.

---

### 3.5 LOW (latent) · A2 — `replace_track_audio._probe_duration_s` text without encoding

**File:** `scripts/replace_track_audio.py` · Lines ~638–655

`subprocess.run([ffprobe, ...], text=True, ...)` without `encoding=`. Already
counted under `net_subprocess_no_encoding` fence. The `except (subprocess.
SubprocessError, ValueError)` clause swallows `UnicodeDecodeError` (a
`ValueError` subclass) non-fatally — the duration gate passes through as if
no duration was measured. Latent: ffprobe duration output is pure ASCII
(`234.567890\n`), so this only fires on a bizarre ffprobe build.
